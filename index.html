ASN Processing Result API

供 SRM 查询 ASN 在 Business Central 中的后续处理状态、失败阶段和完整错误原因。只读接口，不负责上传、重试、取消或删除 ASN。

接口边界

Validation API验证 Excel 并导入 ASN staging tables。
Result API报告 PO 过账、TO 创建和 reconciliation 结果。
Read only不执行写入或重试操作。

asnValidationRequests = Passed 只代表文件验证和导入成功，不代表 Purchase Order 或 Transfer Order 已处理成功。

Endpoint

GET https://api.businesscentral.dynamics.com/v2.0/{tenantId}/{environment}/api/art/integration/v1.0/companies({companyId})/asnProcessingResults

使用与 asnValidationRequests 相同的 Microsoft Entra / Business Central OAuth 身份验证及公司上下文。

Request ID 是什么？

SRM 创建 asnValidationRequests 后，BC 返回记录中的 id 就是 Request ID。它不是文件名、DOCUMENT NUM 或 Invoice Number。

{
  "id": "{validation-request-guid}",
  "fileName": "example.xlsx",
  "status": "Pending"
}

后续将这个 id 作为 sourceRequestId 查询：

GET .../asnProcessingResults?$filter=sourceRequestId eq {validation-request-guid}

一个 Excel 可以包含多个 DOCUMENT NUM，因此一个 Request ID 可能返回多条 ASN Processing Result。

SRM 推荐流程

  1. 创建 asnValidationRequests 并上传 Excel。
  2. 轮询 Validation Request，直到 Passed 或 Failed。
  3. Validation 失败时显示 validationResult，停止后续处理。
  4. Validation 通过后，用返回的 id 查询 asnProcessingResults。
  5. 任何结果 isTerminal=false 时继续轮询。
  6. Failed 或 NeedsReview 时显示 failureStage 与 errorMessage。
  7. 所有结果均为 Succeeded 后，才显示 ASN 处理完成。

Validation 刚通过时结果可能暂时为空，因为后续 Job Queue 是异步处理。空数组不是失败，应稍后重试。

核心字段

字段含义及用法
sourceRequestIdValidation Request 的 ID；推荐查询条件。
documentNoExcel 中的 DOCUMENT NUM。
processingState稳定的 SRM 流程状态，程序判断的主字段。
isTerminaltrue 时停止轮询此 ASN。
failureStagePostPurchaseOrder、CreateTransferOrder 或 Reconciliation。
errorMessageBC 保存的最新完整错误，应展示给用户并记录日志。
statusBC 内部详细状态，仅用于展示，不建议作为主流程判断。
attemptCount处理尝试次数，用于审计。

状态判断

processingStateisTerminalSRM 行为
Pendingfalse继续轮询。
InProgressfalse显示处理中并继续轮询。
Failedtrue显示失败阶段和错误信息。
NeedsReviewtrue停止自动处理并提示人工检查。
Succeededtrue显示成功。
Canceledtrue显示已取消。

BC 枚举空格在 OData JSON 中可能编码为 _x0020_，如 Post_x0020_PO_x0020_Error。请用 processingState 和 failureStage 做程序判断。
